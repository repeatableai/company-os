    # CLAUDE.md ## What this project is A customer portal. Next.js front end, Supabase for the database and user login, Pinecone for search. ## House rules - Never print, log or commit secret keys. Read them from environment variables. - Browser code uses the Supabase publishable (anon) key only. Row Level Security stays on. - Run npm test before every push. - Finish every task with: commit, push, open a PR. ## Where things live - docs/ product notes and decisions - supabase/ database migrations - src/lib/search pinecone helpers

    Level 4 · Database and login

    Plug in Supabase and Pinecone

    Yes, you can use a lasting database and real logins. The database lives on its own servers, so your data stays when sessions end. Your job is to open two doors: keys and network. Flip the switches until data flows to both databases.

    Live wiring puzzleData is stuck. Open the doors.
    Network access: Custom
    *.supabase.co   *.pinecone.io
    Supabase keys added
    SUPABASE_URL   SUPABASE_ANON_KEY
    Pinecone key added
    PINECONE_API_KEY
    Why the gate? The default network level, Trusted, lets the cloud computer reach package stores and GitHub. Supabase and Pinecone are not on that list.2 Connectors are the exception: their traffic goes through Anthropic and skips the gate.2
    Route A · easiest

    Connect Supabase as a connector

    Supabase is an official Claude connector.9 Claude can then look at tables, run SQL and manage your project.

    1. Go to claude.ai/customize/connectors.
    2. Find Supabase. Click Connect. Sign in to Supabase and approve.
    3. Start a new session. Connectors load when a session starts.
    4. Ask: "Using the Supabase connector, list my tables."
    Route B · keys + network

    Give your app code the keys

    1. In Supabase, open Project Settings → API Keys. Copy the Project URL and the publishable (anon) key.
    2. In Claude Code, open the environment selector (the cloud icon), then Edit.
    3. Pro or Max: add the key under API credentials. Claude can use it but never sees it.2 Team or Enterprise: use Environment variables, and only for non-secret or dev keys.
    4. Set Network access to Custom. Add the domains below. Tick Also include default list.
    5. Start a new session and give Claude the task.
    # Environment variables (.env format) SUPABASE_URL=https://your-project.supabase.co SUPABASE_ANON_KEY=your-publishable-key PINECONE_INDEX=docs-dev # Network access → Custom → Allowed domains *.supabase.co *.pinecone.io
    Pinecone

    Add vector search

    1. At app.pinecone.io, open API Keys and create a key.
    2. Pro or Max: store it as an API credential for your Pinecone hosts. Otherwise use PINECONE_API_KEY.
    3. Allow *.pinecone.io in Network access (Custom).
    4. Make a separate dev index so tests can't harm real data.
    5. Ask: "Create a Pinecone index named docs-dev and add search over the files in docs/."

    Pinecone also publishes an MCP server and a Claude Code plugin.11

    Auth meaning #1

    How YOU log in to Claude Code

    Your Claude account plus GitHub. GitHub tokens are handled by Anthropic's proxy outside the cloud computer.2 Nothing to build.

    Auth meaning #2

    How YOUR USERS log in to your app

    Use Supabase Auth: email and password, magic links, or Google sign-in. Claude writes the sign-up and login code. Supabase stores the users.

    Five safety rules

    • Never paste a key into the chat. Chats are saved.
    • Plain environment variables are not a safe. Anyone who uses the environment can read them.2 On Pro or Max, use API credentials.
    • Never commit a .env file. Add .env to .gitignore.
    • Browser code gets the publishable (anon) key only. Keep Row Level Security on. The secret (service_role) key bypasses it.
    • Give Claude dev keys, not production admin keys. If a key leaks, replace (rotate) it right away.

    Magic wand and the trap room

    Magic wand vision

    If you had a magic wand, even if you had to suspend the laws of gravity, here is how I would imagineer the solution.

    Monday, 7:40 a.m. You type one sentence into the Claude app on your phone while the coffee brews: "Add Google sign-in to the client portal." A fresh cloud computer starts and clones your repo. Claude reads CLAUDE.md, which already names your stack, your rules and your test command. The portal-dev environment gives it network access to your Supabase project and a dev key it uses without ever seeing. The Supabase connector shows Claude the real tables. It writes the code, runs the tests, and pushes a branch.

    Your phone buzzes on the train: the pull request is ready, with a plain-English summary. You ask one question, get the answer, and tap Merge. Your laptop never opens. Two more sessions run at the same time, one writing docs and one fixing a bug, each in its own cloud computer, each on its own branch. Your users' data sits safe in Supabase, your search index sits in Pinecone, and every rule you taught Claude lives in the repo.
